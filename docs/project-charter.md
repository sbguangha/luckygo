# 立项决议：多租户营销抽奖平台（LuckyGo）

Examly（在线考试）与 NotifyHub（消息中台）均已废弃。现锁定本方向。生产级边界清单见 [production-edges.md](production-edges.md)，实现必须覆盖该文档，不允许只做 happy path Demo。

## 1. 方向（已确认）

**选定：给商家用的多租户抽奖 SaaS。**  
管理端配置活动与名单，现场大屏 3D 球体抽奖（live），或 C 端报名后到期开奖（scheduled）。

仓库工作名：`LuckyGo`。对外一句话：**商家配奖项和名单，主持人现场大屏抽或到期自动开奖的抽奖工具。**

为什么选它：页面炸、结果立刻看得见（3D 球滚动、中奖卡飞出撒花、中奖名单、核销）。  
必须避开的坑：不要做成「Redis 预减库存的秒杀换皮」。差异化靠 **名单池原子抽、两种开奖模型、幂等与取消回滚、核销、多租户**。

## 2. 这是干什么的

商家做活动：年会现场、店庆、直播间抽奖。他们要的是：

- 配好几档奖项（每档多少人、每次抽几人）、导入或收集参与名单
- 现场一块大屏，主持人一按就出结果，撒花公示
- 实物奖能核销，不会超发 iPhone
- 活动结束能看到参与多少、中了多少

## 3. 两种玩法（V2 已收敛）

**现场大屏抽（live，主玩法）**  
商家导入名单（Excel：编号/姓名/部门/身份/头像）或开放 C 端报名自动上球；主持人打开大屏页（3D 球体，交互复刻 log-lottery），空格驱动「进入抽奖 → 开始 → 停止」：**停止时后端 Lua `SPOP` 名单池原子弹出 N 人**（N=奖项单次抽取个数），中奖卡飞出+撒花。主持人可「取消本次」回滚重抽。结果权威在后端，前端永不预知。

**定时开奖（scheduled）**  
用户报名（写统一名单表），到结束时间 Worker 从参与者里种子洗牌抽出 N 名。Redis 延迟队列触发，开奖任务幂等、种子落审计可复盘。

两种一致性分开讲：live 是名单池原子弹出 + 幂等键回放 + 取消回滚；定时开奖是报名落库 + 到期一次性洗牌。

> V1 的「即时抽大转盘（奖品桶 LPOP）」已下线：名单池 SPOP 继承了同样的原子不超发思路，但更贴合年会/现场场景。

## 4. 范围切片（1–2 个月）

### 必做

- 多租户：商家注册登录，活动数据隔离。
- 管理端：创建活动（live/scheduled）、奖项配置（名称/图片上传/总名额/单次抽取个数/是否全员）、名单导入（Excel）与报名上球、装修配置（标题/列数/卡片色/中奖卡色/背景图/图案点阵）。
- 大屏页：3D 球体（CSS3D）、空格驱动状态机、中奖卡飞出 + 撒花、左侧奖项面板、取消重抽。
- C 端活动页：报名参与、中奖播报、我的奖品（兑换码/收货地址）。
- live 名单池（SPOP）+ 版本号重建；池口径与落库补偿一致性在引擎单测里锁死。
- 定时开奖活动：报名、到期自动开奖、结果页公示中奖名单。
- 核销：注册用户兑换码核销；导入名单线下核销补记。
- 看板：参与人数、中奖件数、各奖剩余名额。
- Compose 一键拉起 MySQL/Redis。

### 加分（第二个月）

- 活动进行中库存/参与数近似实时刷新。
- 黑名单（某用户禁止报名）。
- **压测必做**：并发抽取证明不重复不超发，写入 `docs/loadtest.md`。

### 明确不做（V1）

- 微信支付、充值金币。
- 微信登录 / 复杂裂变（砍一刀、邀请助力）。
- 弹幕、音乐音效（参考项目有，本期不做）。
- Kubernetes、人脸核身。

## 5. 技术栈与部署

| 用途 | 选型 |
| --- | --- |
| 框架 | go-zero（HTTP 网关） |
| 主存储 | MySQL 8（活动、奖项、名单、中奖记录、核销） |
| 名单池 / 延迟任务 | Redis 7（live 池 SPOP、ZSET 延迟队列） |
| 定时开奖 | Redis ZSET 延迟队列 + Worker |
| 追踪 / 指标 | Jaeger + Prometheus + Grafana（按需） |
| 管理端 | React 18 + TypeScript + Vite + Ant Design 5 |
| 大屏 | 同工程 `/live/:id`：three.js CSS3DRenderer + TWEEN + canvas-confetti |
| C 端 | 同工程独立路由（H5 报名/公示页） |
| 部署 | 仅 Docker Compose |

live 模式 **同步 SPOP + 同步落库**（重试 3 次失败进补偿表），链路短、现场演示稳。

## 6. 服务边界（4 个进程）

| 进程 | 类型 | 职责 |
| --- | --- | --- |
| `gateway` | REST | 商家后台 + 大屏 + C 端 API；JWT；图片上传/静态服务 |
| `worker` | 消费者 | 到期开奖（scheduled）；状态翻转；落库补偿重放 |

```text
Admin UI / 大屏3D球 / H5 报名页
        │
     gateway ──── Redis 名单池 SPOP（live 原子抽）
        │                │
      MySQL         延迟队列（状态翻转/到期开奖）
                         │
                       worker
```

## 8. 里程碑（实际执行）

**第 1–2 周**：登录、创建活动与奖项、名单导入、C 端报名上球。  
**第 3–4 周**：live 大屏 3D 球（进入/开始/停止/取消状态机）、中奖名单、核销、看板。  
**第 5–6 周**：定时开奖、不重复不超发压测、README（讲清名单池 SPOP 的原子性与取消回滚设计）。

## 9. 怎么点着验收

两个窗口：商家后台 + 大屏（/live/:id）；C 端无痕窗口当用户。

| 你点什么 | 怎样算过 |
| --- | --- |
| 后台建 live 活动，配三等奖 3 人(单次2)、一等奖 1 人 | 校验：单次 ≤ 总人数；发布后冻结 |
| 名单管理导入 50 人 Excel | 重复导入不产生重复人头（编号幂等） |
| 大屏页按空格 | 横铺卡片墙 → 聚合成球 → 高速旋转 |
| 再按空格（停止） | 中奖卡飞出居中 + 撒花；后台中奖记录恰好本批人数 |
| 同幂等键重放抽取 | 返回相同名单，不重复扣名额 |
| 点「取消」后重抽 | 该批人回池可被重新抽中；取消批次重放被拒 |
| 一等奖名额 1，连抽多批 | 全场只有 1 人中一等奖，已中奖者不再中其他奖（isAll=false） |
| C 端注册用户报名 | 大屏球面出现该用户；中实物奖能在「我的奖品」看兑换码 |
| 核销 | 兑换码核销一次后不可再核销；导入名单中奖可线下核销标记 |
| 建一场「2 分钟后开奖」 | 多人报名，到点自动出名单，结果页可刷新看到 |
| 开奖后再点开奖 | 名单不变（幂等） |
| 后台看板 | 参与人数、各奖剩余名额与页面一致 |

## 10. 简历表述方向（数字待压测后填）

- 设计并实现多租户抽奖 SaaS：现场大屏 3D 球抽取（名单池 SPOP 原子批量出签）+ 到期种子洗牌开奖。
- 名单池 + 版本号重建保证中奖不重复、不超发；幂等键回放防主持人双击/重试；「取消」通过批次翻 undone + 版本重建实现可回滚。
- 定时开奖用延迟队列一次性洗牌，开奖任务幂等；报名唯一约束 + 黑名单防刷。
- 管理端覆盖名单导入、装修配置、核销与看板；Compose 一键拉起；引擎单测锁定「名额 N 的奖项中奖恰好 N」。
